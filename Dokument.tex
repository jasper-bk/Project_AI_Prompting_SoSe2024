    This project explores the use of generative AI, specifically GPT-4 and DALL-E, to create hyper-personalized product pages for websites, emails, and other digital marketing channels. 
    The objective was to automate the generation of personalized text and visual content to enhance user engagement, improve conversion rates, and increase operational efficiency. 
    The project involved integrating Azure's AI APIs into a Python development environment, crafting and refining prompts for content generation, and deploying the system for real-time content delivery.

    Key results included successful integration and automation, leading to significant improvements in user interaction and satisfaction. 
    The project demonstrated that generative AI could effectively tailor marketing content to individual preferences, resulting in higher engagement and conversion rates. 
    Ethical considerations, such as data privacy, bias, and transparency, were addressed to ensure responsible AI usage.

    Future goals involve expanding personalization capabilities, enhancing AI models' context awareness, and exploring integration with emerging technologies. 
    Continuous improvements will focus on advanced data analytics, model enhancement, and maintaining ethical standards. 
    The project concludes that generative AI offers substantial benefits for digital marketing, with potential for ongoing development and refinement.

    \section{Project Structure}

        The implementation of the first Proof of concept hyper-personalized product pages project is structured into several key phases to ensure systematic progress and effective integration of generative AI technologies. 
        The project structure can be broken down as follows:

        \begin{enumerate}
            \item \textbf{Initial Planning and Requirements Gathering}
            \begin{itemize}
                \item Define project goals and scope.
                \item Conduct a detailed analysis of current marketing processes and data sources.
            \end{itemize}
            \item \textbf{Data Preparation}
            \begin{itemize}
                \item Collect and preprocess customer data required for personalization.
                \item Ensure data quality and consistency.
            \end{itemize}
            \item \textbf{Model Integration and Development}
            \begin{itemize}
                \item Set up the development environment and necessary tools.
                \item Develop Python scripts to interact with GPT-4 and DALL-E using the framework LangChain and Azure's API.
                \item Implement and test to ensure proper functionality.
            \end{itemize}
            \item \textbf{System Integration and Testing}
            \begin{itemize}
                \item Integrate the generative AI models into the existing web and email systems.
                \item Conduct comprehensive testing to ensure the accuracy and relevance of personalized content.
            \end{itemize}
            \item \textbf{Deployment and Monitoring}
            \begin{itemize}
                \item Deploy the system to a usable and close to production environment.
                \item Implement monitoring and logging to track system performance and user engagement.
                \item Continuously refine and improve the models based on feedback and performance data.
            \end{itemize}
            \item \textbf{Review and Optimization}
            \begin{itemize}
                \item Analyze system performance and user feedback.
                \item Optimize the models and processes to enhance personalization and efficiency.
                \item Document the project outcomes and lessons learned.
            \end{itemize}
        \end{enumerate}

        \subsection{Implementation of AI Methodologies and Tools}

            To integrate AI methodologies and tools, several steps were taken to ensure a robust and effective implementation. 
            First, the environment was set up by configuring the development environment with Python and the necessary libraries. 
            This included integrating Azure's API to access GPT-4 and DALL-E, providing the foundational tools needed for AI-driven content generation.

            The development phase involved the creation of Python scripts to interact with GPT-4 and DALL-E via the Azure API. 
            With the LangChain framework as foundation, the basic core functions were handled efficiently and also keeps the option open to switch to other generative models at a later time. 

            Instantiating GPT-4 with LangChain is done with the following code snippet.

            \begin{lstlisting}[language=Python, gobble=12, caption=Instantiating GPT-4 with LangChain, firstnumber=29]
            self.llm = AzureChatOpenAI(
                openai_api_key=os.getenv('LLM_API_KEY'),
                azure_endpoint=os.getenv('LLM_ENDPOINT'),
                openai_api_version="2024-02-01",
                deployment_name="gpt4-turbo",
            )
            \end{lstlisting}

            After the instantiating we can start prompting within LangChain.
            We have a so-called chain for this. 
            This is passed several things, namely input values for the prompt, the prompt itself, the instantiated large language model and a string parser for easily readable output.
            
            The prompt initially only consists of a template.
            Templates are explained in more detail later in chapter \ref{sec:prompts}.
            This template is then filled with values within the chain.
            The corresponding code can be seen in the following excerpt:

            \begin{lstlisting}[language=Python, gobble=12, caption=Invoking GPT-4 with LangChain, firstnumber=48]
            prompt = ChatPromptTemplate.from_template(template)
            vector_store = self.load_pdf_into_vector_store(path_to_file)
            docs = vector_store.similarity_search_with_score(query=query,
                                                            k=k_top,
                                                            score_threshold=score_threshold)

            chain = (
                    {"context": lambda x: docs, "request" : RunnablePassthrough(), "customer_information" : RunnablePassthrough()}
                    | prompt
                    | self.llm
                    | StrOutputParser()
            )
    
            print(">> Querying ...")
            result = chain.invoke({"request" : query, "customer_information" : customer_information})
            print(">> ... done querying")
            print("=====================================")
            print("Request:   " + query)
            print("Answer: " + result)
            \end{lstlisting}

            The essential components of the implementation have been shown with those code snippets.
            To have more information about the actual implementation the full code can be found in the \textbf{\hyperref[sec:appendix:text-gen]{appendix}}.

            The snippets shown so far are only the text generating part.
            For the image generation part, the same foundation is used to generate an image prompt from natural text, which is passed on to a DallEAPIWrapper by the LangChain utilities.

            The core implementation is also very simple.
            First the instantiation takes place and then the call.

            \begin{lstlisting}[language=Python, gobble=12, caption=Instantiating DALL-E with LangChain, firstnumber=19] 
                self.image_model = DallEAPIWrapper(
                    api_key = os.getenv('LLM_API_KEY'),
                    base_url = os.getenv('LLM_ENDPOINT')
                )
            \end{lstlisting}

            For the DALL-E invocation, as already mentioned, an image prompt is first created via the existing text generation part.
            The return of the function call is then a URL to the generated image, which can then be downloaded.

            \begin{lstlisting}[language=Python, gobble=12, caption=Invoking DALL-E with LangChain, firstnumber=60] 
                # Actual call to DALL-E
                image_url = self.image_model.run(text_gen_result)
            \end{lstlisting}

            The full code for the image generation can be also found in the \textbf{\hyperref[sec:appendix:image-gen]{appendix}}.

            These scripts implemented functions to generate both text and image content based on user data, enabling the creation of personalized and engaging content for the project.
            
            Finally, testing and validation were critical to ensure the system's accuracy and relevance. 
            Basic unit tests were conducted to verify the correctness of the generated content. 
            Additionally, the outputs were validated with sample user profiles to ensure that the personalization was effective and met the project's goals. 
            This thorough testing phase ensured that the AI-generated content was both accurate and relevant, enhancing the overall user experience.


        \subsection{Prompts Used}
            \label{sec:prompts}

            The success of the generative AI models heavily relies on well-crafted prompts. 
            Templates are used for the prompts used in the project. 
            They are designed in such a way that they only require relevant parameters in order to deliver results that are as uniform but personalized and contextually relevant as possible.

            For this reason, a distinction is made between templates and requests for prompts.
            Templates define the structure, the context and the scope.

            The requests are much smaller and are built into the templates in order to then precisely define the target of the prompt.

            First of all, the templates for text generation:

            \begin{lstlisting}[language=Python, gobble=16, caption=Prompt template for text]
                """
                You are a helpful AI assistant that is very familiar with the given context and tries to personalize as much as possible.
                You will try to incorporate as much information as possible and, if necessary, get creative.
                Use the following context and the informations about the customer to process the request.
            
                Only process reqeuests that refer to the context and do not provide any other explicit information.
            
                If you can not process the request, do NOT try to make up an answer, instead start the answer with
                `Error! Request can not be processed. Reason:` and provide a reason.
            
                <context>
                {context}
                </context>
            
                Customer infortmation: {customer_information}
            
                Request: {request}
                """
            \end{lstlisting}

            Followed by the templates for image prompt generation:

            \begin{lstlisting}[language=Python, gobble=16, caption=Prompt template for images]
                """

    #!/usr/bin/env python3
    
    import os
    import dotenv
    import subprocess

    from langchain_openai import AzureChatOpenAI, AzureOpenAIEmbeddings
    from langchain_core.embeddings import Embeddings
    from langchain_core.vectorstores import VectorStore
    
    from langchain_community.vectorstores import FAISS
    from langchain_core.output_parsers import StrOutputParser
    from langchain_core.prompts import ChatPromptTemplate
    from langchain_core.runnables import RunnablePassthrough
    
    import langchain
    
    # necessary flags
    langchain.verbose = False
    langchain.debug = False
    langchain.llm_cache = False
    
    dotenv.load_dotenv()
    
    class LangChainRag:
    
        def __init__(self) -> None:
            self.llm = AzureChatOpenAI(
                openai_api_key=os.getenv('LLM_API_KEY'),
                azure_endpoint=os.getenv('LLM_ENDPOINT'),
                openai_api_version="2024-02-01",
                deployment_name="gpt4-turbo",
            )
    
            self.embedding = AzureOpenAIEmbeddings(
                api_version="2024-02-01",
                azure_endpoint=os.getenv('ADA_ENDPOINT'),
                api_key=os.getenv('ADA_API_KEY'),
                model="text-embedding-ada-002"
            )
    
            self.llm.temperature=0.5
            self.llm.max_tokens=100
    
    
        def ask(self, path_to_file: str, template: str, query: str, customer_information : str = "", score_threshold=0.4, k_top=3, open_in_pdf_viewer=False) -> None:
            prompt = ChatPromptTemplate.from_template(template)
            vector_store = self.load_pdf_into_vector_store(path_to_file)
            docs = vector_store.similarity_search_with_score(query=query,
                                                             k=k_top,
                                                             score_threshold=score_threshold)

            chain = (
                    {"context": lambda x: docs, "request" : RunnablePassthrough(), "customer_information" : RunnablePassthrough()}
                    | prompt
                    | self.llm
                    | StrOutputParser()
            )
    
            print(">> Querying ...")
            result = chain.invoke({"request" : query, "customer_information" : customer_information})
            print(">> ... done querying")
            print("=====================================")
            print("Request:   " + query)
            print("Answer: " + result)
            print()

            if len(docs) == 0 and result != "No answer found!":
                print("No documents found. To get an answer, you can increase the 'score_threshold'. This will reduce the quality of the answer.")
    
            self.print_document_info(docs, score_threshold, open_in_pdf_viewer)

            return result
    
        def load_pdf_into_vector_store(self, pdf_file: str) -> VectorStore:
            if os.path.exists("vectorstore.db"):
                print(">> Loading from existing vectorstore ...")
                vector_store = FAISS.load_local("vectorstore.db", embeddings=self.embedding,
                                                allow_dangerous_deserialization=True)
                print(">> ... done loading vectorstore")
                return vector_store
            else:
                print(">> Start loading pdf into vector store ...")
                loader = PyPDFLoader(pdf_file)
                pages = loader.load_and_split()
                print(">> ... done loading pdf.")
                print(">> Creating vector store ...")
                vector_store = FAISS.from_documents(pages, embedding=self.embedding)
                print(">> ... done creating vector store")
                vector_store.save_local("vectorstore.db")
                return vector_store
    
        @staticmethod
        def print_document_info(docs, score_threshold: float, open_in_pdf_viewer: bool) -> None:
            print("score_threshold : " + str(score_threshold))
            print("------------------------------------")
            for document, score in docs:
                page = str(document.metadata['page'] + 1)
                print("  Page          : " + page)
                print("  Score         : " + str(score))
                print("  Document      : " + document.metadata['source'])
                if open_in_pdf_viewer:
                    subprocess.Popen("evince " + document.metadata['source'] + " --page-label=" + page,
                                     stdout=subprocess.PIPE,
                                     shell=True, preexec_fn=os.setsid)
                else:
                    print("  Text          : >> " + document.page_content[:50] + " ... <<")
                print()
